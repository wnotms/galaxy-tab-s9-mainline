# SM-X710 首次启动尝试

测试日期：2026-09-18；设备 SM-X710，revision 6，启动固件 X710ZCU5CYH4。基础源码为提交 `ef83018`，测试工具为 `scripts/twrp-boot-test.py`。

## 已完成

- 四个镜像的 Android v4 布局、实机地址、分区尺寸、AVB 哈希、DTB 与 ramdisk 检查通过。
- 连接 TWRP 后确认 root、bootloader unlocked、AVB flags 2；四个当前启动分区的哈希与提取备份完全一致。
- 镜像上传到 TWRP `/tmp/` 后再次校验 SHA256。
- 写入 boot、init_boot、vendor_boot、dtbo，四个分区逐个回读校验通过。
- 写入后确认 recovery 和 vbmeta 的 SHA256 保持不变。
- 已请求正常重启；Windows USB / 网络枚举未观察到 Linux NCM 网卡，ADB 连接也未恢复。
- 用户照片显示停留在 Samsung Galaxy splash，并显示非官方软件警告；没有显示具体校验错误或 panic 信息。此基线没有原生显示驱动，画面停留本身不能判断内核是否执行。

## 当前结论与下一步

镜像写入成功，**未确认主线内核成功启动，也未达到 USB 诊断环境的验收条件**。没有 USB 连接不能区分 ABL 拒绝、内核早期停止或 USB 驱动初始化失败。

需要物理按键回到 TWRP，首先保存 `/proc/last_kmsg`、pstore 和 recovery 日志，与测试前快照比较，再决定下一项修改。当前设备的四个启动分区仍为实验镜像，尚未恢复原备份；恢复工具不会写入 recovery / vbmeta。

本地完整记录位于被 Git 忽略的 `artifacts/boot-tests/first-sm-x710/`：preflight / flash report、Windows USB/网卡前后快照及 result。本次写入的镜像组合另外保存于 `tested-bundle/`，避免后续构建覆盖后无法核对当前实验分区。恢复备份在 `artifacts/device-snapshot-sm-x710-20260918/partitions/`。

回到 TWRP 后恢复采集时启动集合：

```sh
python3 scripts/twrp-boot-test.py \
  --adb /mnt/d/android/platform-tools/adb.exe \
  --snapshot artifacts/device-snapshot-sm-x710-20260918 \
  --bundle artifacts/boot-tests/first-sm-x710/tested-bundle \
  --report artifacts/boot-tests/first-sm-x710/restore \
  --restore
```

工具允许目标分区当前为本次实验镜像或原备份，恢复后回读哈希；遇到其他内容会停止。应先回收日志，再恢复。此命令只恢复启动集合，不自动重启 Android。
