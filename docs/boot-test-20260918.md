## 实机日志与结论

`recovery-after/last_kmsg.txt` 包含本次主线内核输出，之后是固件崩溃及恢复启动记录。关键证据如下：

```text
[    0.000000] Linux version 7.2.0-rc3-gts9wifi-bringup ...
[    0.000000] Machine model: Samsung Galaxy Tab S9 Wi-Fi
[    0.008659] SMP: Total of 8 processors activated.
[    0.020349] Unpacking initramfs...
[    0.021751] Freeing initrd memory: 1136K
[    0.023705] gts9wifi-sec-kernel-log sec-kernel-log: persistent console at 0x0000000880200000 (2097152 bytes)
[    0.031484] NET: Registered PF_PACKET protocol family
collect_rr_data : upload_cause = TZBSP_ERR_FATAL_NOC_ERROR
```

**ABL 已交接主线内核，8 个 CPU、initramfs 解包和持久日志路径通过实测；未达到用户态 / USB 诊断环境的验收条件。** 最后一条主线日志时间约为 31 毫秒，但它并不证明 PF_PACKET 初始化就是故障源。TZ 的相关细节为加密日志，目前无法确认触发 NoC 错误的具体驱动、访问地址或保护单元。

日志另有三个明确的 DT 保留区重叠：ABL 添加 `kaslr_region`、`uh_heap_region`、`uh_guest_region`，与原 DTS 中 `kaslr@b01ff000`、`uh-heap@b0200000`、`uh-guest@b1000000` 的范围重复。这说明离线输入 DTB 无重叠不等于 ABL 修补后的 DTB 无重叠。另有 `CONFIG_BOOT_CONFIG` 未启用警告，尚无证据表明它导致此次 NoC 故障。

## 后续诊断镜像

当前源码将上述三个节点改为 ABL 使用的精确名称，并保留原地址和 `no-map`；cmdline 加入 `initcall_debug`，便于下次采集定位初始化阶段。新版已重新执行 `make bundle`、四镜像验证器和 `make check`，均通过。主机用 FDT overlay 模拟再次更新这三个同名节点，保留区覆盖及无重叠检查也通过；这只验证同名合并行为，不替代三星 ABL 的实机验证。

**新版位于 `artifacts/boot-bundle/`，尚未刷入，也不能认定已修复 NoC 故障。** 下一次启动应先验证有效保留区没有重复，再利用 initcall 跟踪缩小故障范围。

## 本地归档与恢复

完整记录位于被 Git 忽略的 `artifacts/boot-tests/first-sm-x710/`：preflight / flash / restore report、Windows USB/网卡前后快照、result 和 `recovery-after/` 原始日志。本次实际写入的镜像组合保存在 `tested-bundle/`；后续构建不会覆盖它。恢复备份在 `artifacts/device-snapshot-sm-x710-20260918/partitions/`。

本次已执行以下恢复命令，`restore/report.json` 的最终阶段为 `restored`：

```sh
python3 scripts/twrp-boot-test.py \
  --adb /mnt/d/android/platform-tools/adb.exe \
  --snapshot artifacts/device-snapshot-sm-x710-20260918 \
  --bundle artifacts/boot-tests/first-sm-x710/tested-bundle \
  --report artifacts/boot-tests/first-sm-x710/restore \
  --restore
```

工具允许目标分区当前为指定实验镜像或原备份，恢复后回读哈希；遇到其他内容会停止。应先回收日志，再恢复。此命令只恢复启动集合，不自动重启 Android。
